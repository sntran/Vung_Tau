## 1. Goal

I open the web build, and I ride in a short time. The page gets first only what the start needs. It gets the rest while I play. A phone can open the page.

On 2026-11-25 I opened the web build of plan 0018 on my computer. The loading screen of Godot took about one minute. Then I could not ride, because the world was not ready.

## 2. Out of scope

- Another engine, and a game that a server draws (D1).
- The desktop builds and the apps of Android and iOS: they keep one pack.
- A change of the look of the game on a computer.
- The illustrated map of plan 0029.

## 3. What the builder measured (plan 0009, R16, 2026-11-23)

- The pack is 321.1 MB, and `index.wasm` is 39.5 MB. Godot gets the whole pack before the first frame and keeps it in the memory of the page.
- In the pack: the scenes of the models of World 227.5 MB (the buildings: near 78.6, mid 14.8, far 1.7; the people: mid 57.7, far 35.7; the other things: near 29.4, mid 7.1, far 2.5), the textures 49.6 MB, `data/geo/build` 34.5 MB of JSON, `data/geo/raw` 4.4 MB that the game does not read.

- The web build starts on Low (`scripts/quality.gd`). On Low a building of World does not show its near level.

- **Q6.** (2026-11-26) D16: a pack of Godot stays in memory two times on the web. May the game get the mid and near levels of the models of World as single files that it deletes after their load? (I answer.) The builder says: Godot reads a pack only from a file. The page writes the pack to `/tmp/packs/` of the engine (memory of the page), and the engine reads each resource from that file when the game asks for it; a model loads when the player comes near it, and loads again after the game frees it. So the file must stay while the game runs, next to the resources that are loaded from it. The measure (item 6, 720 × 1280, 25 Mbit/s, an empty cache): the page has 1564 MB when the player can move, 1752 MB when the pack `models` (110.7 MB) is there, and 1928 MB when the pack `people` (56.8 MB) is there; the start pack (91.6 MB) also stays as a file, as in the loader of Godot. The proposal: `deploy.sh` makes each level of a model a file of its own, in parts by hash as now; the page keeps them in its cache; the game writes a level to `/tmp/`, loads it, and deletes the file at once; a level that the game frees comes again from the cache of the page. This changes `WorldModel` (a level is then a file of `/tmp/`, not a path of the pack) and the measure of R16. The memory of the files is then the levels that load at that time, not 167 MB.
